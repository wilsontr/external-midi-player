# T20: Track metadata titles and LCD metadata viewer

- **ID**: T20
- **Milestone**: After the MVP
- **Status**: done
- **Estimate**: 1–1.5 days
- **Depends on**: T2, T3, T10, T11, T17
- **Modules**: `src/parser.ts`, `src/playlist.ts`, `src/ui.ts`, `src/styles.css`, `tests/unit/parser.test.ts`, `tests/unit/playlist.test.ts`, `tests/e2e/metadata.spec.ts`, `tests/e2e/t11-faceplate.spec.ts`, `README.md`, `docs/Browser MIDI Playlist Player — MVP Design.md`
- **Requirements**: R3, R13

## Objective

Show a song's `Track Name` instead of its file name when the file provides a meaningful one, and add a per-row metadata key that opens an amber LCD dialog listing every `Track Name`, `Text Event` and `Copyright Notice` in the file. SMF text must decode correctly for Japanese encodings as well as Western text, because the Stanford-style files use these fields for their real metadata and Shift_JIS titles currently arrive as mojibake.

## Scope

- **Parser.** Extend `ParsedSong` with a `metadata` value: `trackNames`, `textEvents` and `copyrights` arrays of `{ track: number; text: string }` in file order (MTrk order, then event order; `track` is the 0-based chunk index and the UI shows it 1-based), plus `title: string | null` and `truncated: boolean`. Collect only the three metas named in the ticket (`trackName` 0x03, `text` 0x01, `copyrightNotice` 0x02); `instrumentName`, `lyrics`, `marker` and `cuePoint` stay out of scope and, like all non-tempo metas today, never enter the playback event list.
- **Decoding.** Decode each value independently, since a file may mix ASCII track names with a Shift_JIS title. `midi-file` 1.2.4 decodes meta text as Latin-1 (`String.fromCharCode`), so recover the original bytes with `Uint8Array.from(text, (c) => c.charCodeAt(0))` and lock that assumption with a test. Detect the encoding in this order: UTF-8 BOM → ISO-2022-JP escape sequences (ISO-2022-JP is 7-bit and therefore valid UTF-8, so this check must come first) → all-ASCII → valid UTF-8 → Shift_JIS/EUC-JP → Windows-1252. Decode both Japanese candidates with `{ fatal: true }` and score them by their count of non-half-width hiragana/katakana, kanji and full-width punctuation (penalising U+FFFD and C0 controls). If neither candidate decodes to at least one such character, use Windows-1252; this keeps a lone 0xA9 in `Copyright © 2004` as `©` rather than half-width katakana. If only one qualifies, use it; if both qualify, use the higher score and prefer Shift_JIS on a tie. Use the built-in `TextDecoder` labels (`utf-8`, `shift_jis`, `euc-jp`, `iso-2022-jp`, `windows-1252`); no new runtime dependency.
- **Normalisation.** Strip NULs, normalise to NFC and trim. For the popup keep tabs and newlines (Stanford text is tab-separated) but replace other C0/C1 controls with spaces; for the title collapse all whitespace. Omit empty/whitespace-only values from the arrays, and mark `truncated` when the per-song cap drops values.
- **Title.** Only track 0 (Track 1 in the viewer) may name the song: use its first usable `trackName` value. If it has no usable name — empty, `untitled`, or no `trackName` event at all — do not consider any later track; keep the file-derived name. Usable means trimmed, NFC, non-empty and not `untitled` case-insensitively. When nothing is usable, `title` is null and the playlist keeps the file-derived name. Apply a cap (suggested: 256 values per field and 16,000 characters of text per song) so a pathological file cannot bloat `localStorage` or the DOM; the dialog explains when values were omitted.
- **Playlist model.** Add `metadata?: SongMetadata` to `PlaylistEntry`, but keep `name` as the file-derived name for identity, persistence, the M3U path line and the fallback. Add `entryDisplayName(entry)` (or equivalent) returning `metadata.title ?? name`, and use it at every user-visible site: playlist row, LCD current title, Instruments caption, Play/Remove/Metadata accessible names, status messages and the M3U `#EXTINF` title. `file.name` remains the stored file name and the M3U path.
- **Persistence.** Carry metadata on every `parsed` dispatch (playback and background) and store it as an optional field on `StoredEntry`. Keep `version: 1`: the field is additive and old payloads remain valid. Validate it on read; malformed metadata is ignored and reparsed. On restore, queue entries whose duration **or** metadata is missing, so an existing playlist gets titles without being played, while a reload of a new playlist shows them immediately and does not reparse. Reuse the existing serial background queue and debounced persistence.
- **On-demand read.** Add a `metadataFor(id)` method for the viewer: return stored metadata immediately, otherwise parse the file once and store the result, deduplicating against the background queue so an entry never has two parses in flight. A metadata-only read failure is reported inside the dialog and does not change transport or retrospectively mark a ready entry as an error; normal playback parsing remains authoritative.
- **Viewer.** Add a small info key to every healthy row (`data-testid="metadata-button"`, `data-action="metadata"`, accessible name `Metadata for <display name>`), disabled on error rows. It must not select the row, start a drag or trigger the row's double-click play; add an info icon to the existing icon set. Use one native `<dialog>` in the root markup (`data-testid="metadata-dialog"`), opened with `showModal()`: a heading with the display name, the original file name in small dim text, then three labelled sections in the order **Track Name**, **Text Event**, **Copyright Notice** (`metadata-track-names`, `metadata-text-events`, `metadata-copyrights`; each value row carries its 1-based track number, e.g. `data-track="1"`). Each section lists every retained value as `Track N` plus the decoded text in file order, or “None recorded.”; a truncation note appears when the cap applied. The body scrolls inside the dialog (`max-height`), and values use `white-space: pre-wrap; overflow-wrap: anywhere; tab-size: 4` so tab-separated Stanford text and unbroken Japanese strings stay readable. A Close key (`metadata-close`), Escape and a backdrop click close it, and focus returns to the opening key.
- **Viewer safety and accessibility.** Insert every metadata value with `textContent`, never `innerHTML`, so a `Text Event` containing HTML is shown literally and cannot execute. Give the dialog `aria-labelledby` (native `showModal` supplies the modal semantics), keep the focus ring, and add a CJK fallback to the LCD font stack for values. If metadata is still loading, show “Reading metadata…” with `aria-busy="true"` on the body and clear it when the values arrive; if the entry disappears while open, close the dialog. Opening or closing must not pause or otherwise change playback, and the viewer must not add a second `aria-live` region — status stays in the existing one.
- **Shortcuts.** Suppress the document-level shortcuts while the dialog is open. `Escape` currently calls `panic()`; with the viewer open it must only close the dialog, and Space/arrows must not change transport.
- **Styling.** Reuse the existing `--lcd-*` tokens (amber ink, dot grid, inset glass, pixel font for chrome/labels) rather than inventing a second surface. Use a width of `min(92vw, 40rem)`, a maximum height around 80vh with a scrollable body, and verify 360 px and 1280 px layouts with no horizontal page scroll. Long or numerous values must scroll inside the dialog, not grow the page.
- **Tests and docs.** Unit tests for decoding (ASCII, UTF-8, Shift_JIS, EUC-JP, ISO-2022-JP, Windows-1252 `©`, invalid bytes), the first-track-only title rule, track indices and file order, the metadata cap, and a regression that playback events/duration are unchanged. Playlist tests for metadata on the `parsed` action, the display-name helper, persistence round-trip, legacy payloads without metadata, malformed metadata and the cached/on-demand read. One Playwright spec covering a Shift_JIS title replacing the row and LCD title, `untitled` falling back, the dialog's three sections and track labels, Escape closing without Panic, focus return, literal HTML, reload persistence, the M3U title/path split, no transport change, and the 360 px layout. Update the design doc's entry model, Playlist and UI layout sections, the README behaviour notes, and the task index.

## Acceptance criteria

- [x] `untitled` (case-insensitive, trimmed), empty names and a first track with no Track Name at all leave the file-derived name in place, even when a later track is named; the bundled sample keeps its file name while its Text Events still appear in the viewer.

## Notes

- **Why the real files need this.** `bgaregga1.mid` names track 0 with Shift_JIS bytes ending `95 c0 96 d8 8a 77`; those bytes arrive as Latin-1 C1 controls and `ÀØw` today, while Shift_JIS gives `並木学`. `Green_Brinstar.mid` and `Zealv1.15.mid` name track 0 `untitled` (and their later tracks include `Voice 2` and `Track 1`), which is why the title rule never scans later tracks. `Sonic_2_Chemical_Plant.mid` has no track-0 name but puts a name on track 1; under the revised first-track-only rule it keeps its file name, and the later names remain visible only in the viewer. `GunstarHeroes_AncientRuins.mid` has a usable track-0 title. The bundled Debussy sample has no Track Name (only Stanford Text Events), so its filename stays and the viewer is the place those `@DRUID`/`@ROLL_TYPE` values finally surface.
- **Observed generic names.** `Green_Rod.mid` is a format-0 file split across 13 MTrk chunks named `Track 1` … `Track 13`; the rule above yields the useless title `Track 1` instead of the filename `Green_Rod`. The ticket follows the requested rule (ignore only `untitled`); if review wants generic `Track N` placeholders ignored as well, keep that list in one exported constant so it is a one-line change and add the fixture's expectation.
- **Encoding detection is a heuristic, not a promise.** Shift_JIS and EUC-JP overlap for some byte pairs, and a lone 0xA0–0xFF byte can be either Western text or half-width katakana; the scoring rule prefers Western text unless a real double-byte Japanese character appears. NEC/IBM Shift_JIS vendor rows, UTF-16 text and a user-selectable “decode as…” override are out of scope. Keep the detector a pure function (`decodeMidiText(bytes)`) with table-driven unit tests so it can be tuned without touching the playlist or UI.
- **Parser coupling.** The byte-recovery trick depends on `midi-file` 1.2.4's Latin-1 `readString`. The dependency is pinned by the lockfile and declared directly, and a unit test with raw Shift_JIS bytes makes a future parser upgrade fail loudly instead of silently breaking Japanese titles. If that day comes, replace the recovery with a small raw meta scanner over the original file bytes.
- **Button placement.** A per-row info key is chosen because metadata belongs to a file and the key works for a stopped song without changing the selection first; the row keys already have the click/double-click guards this needs. If the third key crowds the 360 px row more than review likes, a single `Info` key in the playlist toolbar acting on the selected row is the fallback, not a second button in both places.
- **Display only.** `name` remains the file-derived identifier so persistence, M3U matching and reload semantics do not change. Metadata is a small, read-only summary; the parsed event list is still discarded after the duration/metadata pass, and the scheduler is untouched.
- **No new dependency.** The detector uses `TextDecoder`, which is already available in the target browsers and in the Node 22 Vitest environment; `<dialog>` is supported by the target Chrome/Edge and Firefox versions.
- **Visual check.** Before closing the task, screenshot the dialog at 1280 px and 360 px with a Shift_JIS-titled file and with the Stanford sample, and use the repo's Chrome DevTools MCP / VLM to judge the LCD look and Japanese legibility; the automated tests assert DOM text, not glyphs.

### Decisions as implemented

- **Per-row key, single dialog.** The info key sits between Play and Remove on every healthy row; a single native `<dialog>` is reused for all rows. Opening it does not move the row selection. The playlist toolbar alternative from the notes was not used.
- **Encoding detector.** `decodeMidiText` accepts the Latin-1 string from `midi-file` or raw bytes. The byte->string round-trip is exercised by a Shift_JIS fixture. Detection order is BOM, ISO-2022-JP escapes, ASCII, UTF-8, then Shift_JIS/EUC-JP scored by non-half-width Japanese characters, then Windows-1252; the lone `©` case is covered. Decoders are cached per label/fatal pair.
- **Title rule and fixtures (revised).** Only Track 1's first usable Track Name can name the song; if Track 1 has no usable name (empty, `untitled`, or no event), later tracks are ignored and the file name is used. The real `bgaregga1.mid` reads `Battle Garegga　～Fly to the Leaden Sky～ Composed by 並木学`; `Green_Brinstar`/`Zeal` stay on their file names; `Sonic_2` now keeps its file name instead of using track 2's `Chemical Plant`; `Green_Rod` still yields `Track 1`, as only `untitled` is ignored.
- **Retention.** 256 values per field and 16,000 characters per song, with the title resolved before capping. Metadata is an optional `StoredEntry` field under the existing version-1 payload; old stores are queued for a metadata parse in the background. A stored title that is empty or `untitled` is normalised back to null.
- **One parse per entry.** Playback, the background queue and the viewer share a `parseInFlight` map; repeated viewer clicks also share a `metadataReads` promise. A metadata-only failure is shown in the dialog but leaves the row and transport alone.
- **M3U split.** `#EXTINF` uses the display name; the following path line keeps `file.name`. Import matching is unchanged and still keyed on file names.
- **Dialog details.** Native `showModal` supplies the modal semantics and focus return; Close, Escape and a backdrop click dismiss it. The global key handler returns while the dialog is open, so Escape cannot reach Panic. The CJK fallback is scoped to the title, row name, Instruments caption and dialog text, so the T11 LCD-font assertion keeps its pixel-first stack (updated only to allow the fallbacks).
- **Verification.** `tests/e2e/metadata.spec.ts` has eight cases in Chromium and Firefox (title/fields, fallbacks, Escape and transport, backdrop and shortcuts, literal HTML, reload, M3U, 360 px). The dialog was also checked against the real `bgaregga1.mid` at 1280 px and 360 px, and the bundled Stanford sample at 1280 px.
- **Follow-up (2026-11-19).** The main LCD title is clamped to two lines with an ellipsis; the 360 px check asserts `-webkit-line-clamp: 2` and a height within two line-heights. The metadata table's track-number column is 5.5 rem with a 24 px column gap (5 rem / 18 px at 360 px), and the E2E checks the computed gap at both widths.
